# AFL++ Fuzzing Campaign Plan for YAJL Heap-Buffer-Overflow

## Objective
Find AddressSanitizer (ASAN) or UndefinedBehaviorSanitizer (UBSan) issues in `yajl_tree_parse()`, specifically targeting heap-buffer-overflow vulnerabilities.

## Current Setup Analysis

### Fuzzer Implementation
- **File**: `yajl_tree_parse_fuzzer_enhanced.cpp`
- **Key Features**:
  - Uses `malloc()` instead of `calloc()` to avoid zero-initialization (increases ASAN detection)
  - Enhanced `Walk()` function with byte-by-byte access using volatile variables
  - Targets CVE-2017-16516 (heap-buffer-overflow in string handling)
  - Processes JSON inputs up to 100MB
  - Skips inputs with embedded NUL bytes

### Build Configuration
- **Presets Available**:
  1. `ytp.asan` - Standard ASAN+UBSan+LSan build
  2. `ytp.asan.laf` - LAF_ALL (compare splitting) build
  3. `ytp.asan.cmplog` - CMPLOG instrumentation for comparison tracking
  4. `ytp.cfisan` - Control Flow Integrity sanitizer

- **Sanitizer Flags**:
  - Address Sanitizer with use-after-return detection
  - Undefined Behavior Sanitizer
  - Leak Sanitizer
  - Local bounds checking
  - Stack use-after-return detection

### Seed Corpus
- **Location**: `in-json-min/`
- **Size**: 200+ minimized JSON test files
- **Coverage**:
  - Unicode surrogate pairs (high/low surrogates)
  - Deeply nested structures (128+ levels)
  - Large arrays and objects
  - Edge cases: NUL bytes, control characters, invalid UTF-8
  - Numeric edge cases (overflow, underflow, scientific notation)
  - Malformed JSON with comments
  - Escape sequence variations

### Dictionaries
1. `llvm.dict` - Auto-generated by AFL++ DICT2FILE
2. `json.dict` - JSON-specific tokens
3. `json_surrogates.dict` - Unicode surrogate pairs
4. `unicode.dict` - Unicode characters

### AFL++ Swarm Configuration
- **Parallel Instances**: N/2 on macOS (physical cores / 2)
- **Strategy Mix**:
  - 30% CMPLOG instances (70% level 2, 10% level 3, 20% level 2AT)
  - 50% ASAN builds, 50% LAF_ALL builds
  - 65% disable trimming
  - 50% keep timeouts
  - Dictionary usage: 80% llvm, 75% json, 70% surrogates, 85% unicode
  - 40% expand havoc
  - 20% old queue processing

## Execution Plan

### Phase 1: Build Verification (5 minutes)
1. Clean any existing builds
2. Build all fuzzer variants:
   ```bash
   cmake --workflow --preset ytp.asan
   cmake --workflow --preset ytp.asan.laf
   cmake --workflow --preset ytp.asan.cmplog
   ```
3. Verify binaries exist in `build/bin/`
4. Test single input to confirm ASAN is working

### Phase 2: Initial Fuzzing Run (30-60 minutes)
1. Clear old output directories
2. Create fresh `asan_log/` directory
3. Launch AFL++ swarm:
   ```bash
   ./run_afl_swarm.sh
   ```
4. Monitor initial coverage growth
5. Check for early crashes

### Phase 3: Monitoring & Analysis (Continuous)
1. **Watch for crashes**:
   - Check `out-*/*/crashes/` directories
   - Monitor `asan_log/` for ASAN reports
   - Look for `id:000000,sig:06` (SIGABRT from ASAN)

2. **Coverage metrics**:
   - Track edge coverage growth
   - Monitor favored queue exhaustion
   - Check for coverage plateaus

3. **ASAN report indicators**:
   - `heap-buffer-overflow` in error messages
   - `READ` or `WRITE` of size N at address
   - Stack traces pointing to `yajl_tree_parse` or string handling

### Phase 4: Seed Enhancement (If needed)
If no crashes after 1 hour, enhance corpus:

1. **Add targeted seeds**:
   - Very long strings (>10KB) with surrogates
   - Deeply nested objects with string keys containing surrogates
   - Arrays with alternating surrogate pairs
   - Strings with incomplete UTF-8 sequences at boundaries

2. **Mutation strategies**:
   - Focus on string length boundaries
   - Surrogate pair manipulation
   - Buffer boundary conditions

### Phase 5: Crash Triage
When crash found:
1. Reproduce with standalone binary
2. Capture ASAN report
3. Minimize crashing input
4. Verify it's a heap-buffer-overflow
5. Document:
   - Input that triggers crash
   - ASAN report
   - Stack trace
   - Root cause analysis

## Expected Vulnerabilities

Based on CVE-2017-16516 and the fuzzer design:

1. **Heap-buffer-overflow in string handling**:
   - Surrogate pair processing
   - UTF-8 decoding
   - String concatenation/copying

2. **Potential trigger patterns**:
   - High surrogate without low surrogate
   - Low surrogate without high surrogate
   - Invalid surrogate sequences
   - Surrogate pairs at buffer boundaries

## Success Criteria

✅ **Primary Goal**: Find at least one heap-buffer-overflow detected by ASAN

**Evidence Required**:
- ASAN report showing `heap-buffer-overflow`
- Reproducible crashing input
- Stack trace in `yajl_tree_parse` or related functions

## Monitoring Commands

```bash
# Watch fuzzer stats
watch -n 5 'afl-whatsup out-*/'

# Check for crashes
find out-*/*/crashes/ -type f -name 'id:*' 2>/dev/null

# Monitor ASAN logs
tail -f asan_log/asan.*

# Check coverage
grep "paths" out-*/*/fuzzer_stats | sort -t: -k2 -n
```

## Abort Conditions

Stop fuzzing if:
1. Heap-buffer-overflow found ✅
2. Coverage plateaus for >2 hours with no new paths
3. All instances show "favored queue exhausted"
4. System resources exhausted

## Next Steps After Finding Bug

1. Minimize the crashing input
2. Create proof-of-concept
3. Analyze root cause
4. Document vulnerability details
5. Consider patch development
